# 🛡️ new-vps-setup

> Пошаговый, безопасный путь от чистого Ubuntu VPS до сервера, который обслуживает себя сам —
> для тех, кто делает это впервые. Работает и с сервером, который уже кто-то настраивал.

Это **agent skill** для [Claude Code](https://claude.com/claude-code) и совместимых агентов
и одновременно **читаемая инструкция** для человека. Три вещи, которых нет в обычных
«20 things to do after installing Ubuntu»:

- **Гейт от «я заперся».** Семь обязательных проверок и таймер авто-отката перед любой правкой
  SSH или файрвола. Ошибка откатывается сама через 5 минут, а не выездом в консоль провайдера.
- **Диагностика с вердиктами.** Один read-only скрипт показывает, что уже сделано, что нет,
  и в каком порядке чинить. Сервер, настроенный по другой схеме, не получает ложных «плохо».
- **Правила для агента.** Команды на сервер только скриптом из файла, проверка по содержимому
  результата, sudo-пароль остаётся у человека. Без этого агент ломается на экранировании и
  выглядит успешным.

**Сервер:** Ubuntu 22.04 / 24.04 / 26.04 LTS. **Локальная машина — любая:** Linux, macOS или
Windows (на Windows отличается только копирование SSH-ключа, описано в скилле).

## 🎚️ Три уровня — где остановиться

| Уровень | Что это | Разделы | Время |
|---------|---------|---------|-------|
| **1. Сервер можно оставить включённым** | Вход только по ключу, root и пароль закрыты, UFW, автообновления безопасности, fail2ban | 0, 1, 2 | ~1 час, одна сессия |
| **2. Это прод** | Бэкап с проверенным восстановлением и алертом о падении, HTTPS, мониторинг, паспорт сервера, контрольная перезагрузка | 3–9 | полдня + неделя наблюдения |
| **3. По потребности** | VPN (AmneziaWG, xray), DOCKER-USER, смена порта SSH, апгрейд LTS → LTS, глубокий аудит, автообновление образов с откатом | отдельный скилл | [`ubuntu-server-admin`](https://github.com/igor-batrakov/ubuntu-server-admin) |

Уровень 1 без уровня 2 — «не взломают», но не «не потеряю данные». Прод начинается после
уровня 2. Третий уровень намеренно вынесен: для новичка сила этого скилла в том, что здесь нет
лишнего.

## ⚡ Быстрый старт: проверить существующий сервер

Ничего не устанавливая и не меняя — одна команда показывает состояние сервера и план:

```bash
git clone https://github.com/igor-batrakov/new-vps-setup.git
scp new-vps-setup/scripts/diagnose.sh <user>@<server>:/tmp/
ssh -t <user>@<server> sudo bash /tmp/diagnose.sh
```

Вывод — `[OK]` / `[!!]` / `[..]` по каждой проверке и итог двумя блоками: «сначала» (уровень 1)
и «потом» (уровень 2), с номерами разделов SKILL.md. Скрипт только читает: `sshd -T`, UFW,
sudoers, таймеры, Docker, fail2ban, сертификаты через `nginx -T`, бэкапы и алерты.

## ✨ Что внутри

| Раздел | Что делает |
|--------|-----------|
| 🤖 **Правила для агента** | Команды только из файла (без heredoc в `ssh '...'`), конфиги через `scp` + `install`, проверка по содержимому, ручные шаги по таблице сред (CLI / Desktop / VS Code / Codex), два режима sudo, пароли никогда не в чате |
| 🚧 **Гейт от «я заперся»** | 7 проверок перед правкой sshd/UFW: консоль провайдера, вторая сессия, ключ проверен, бэкап, таймер отката ДО копирования файла, синтаксис, порт и IP открыты заранее |
| 🔍 **0. Диагностика** | `scripts/diagnose.sh` с вердиктами и планом; карта «нашёл → иди в раздел»; у каждого раздела «уже сделано, если…» |
| 🔐 **1. Hardening** | sudo-пользователь с паролем, запереть дефолтного пользователя хостера, ed25519-ключ, `PasswordAuthentication no`, `AllowUsers`, fail2ban с `backend = systemd`, лимит журнала, swap |
| ♻️ **1.5 Автообновления** | `unattended-upgrades`: пакет, оба таймера apt и конфиг, потому что образы хостеров бывают с удалённым пакетом при «правильном» конфиге |
| 🧱 **2. Файрвол** | UFW: закрыто всё, открыто нужное, админки только доверенным IP |
| 🐳 **3. Docker** | Лог-ротация, `restart: unless-stopped`, «Docker обходит UFW» — порты на `127.0.0.1` |
| 🌐 **4. nginx + HTTPS** | Reverse proxy, Let's Encrypt с автопродлением |
| 💾 **5. Бэкапы** | restic + offsite, ротация, **учебное восстановление обязательно**, алерт при падении (`OnFailure`) + dead-man's switch (healthchecks.io) |
| 📈 **6. Мониторинг** | Внешний uptime + Telegram: диск, память, «ждёт reboot», упавшие сервисы |
| 🗓️ **7. Регламент** | Что делает автоматика, что человек раз в неделю/месяц/полгода |
| ⛔ **8. Pitfalls** | 15 вещей, которые нельзя делать |
| ✅ **9. Финал** | `ssh-audit` + `lynis`, контрольная перезагрузка, паспорт сервера `/root/server-notes.md`, чеклист |
| 🆘 **10. Runbook «Я заперся»** | По симптому → причина → что делать через консоль провайдера |
| 🆘 **Runbook «Сервер умер»** | В `references/backups.md`: новый VPS, restic, данные и БД из дампа, `/etc` только выборочно |

## 🚀 Как пользоваться

**Через агента.** Попроси:

> «Помоги настроить новый Ubuntu VPS под продакшн»
> «Проверь мой сервер и скажи, что не так»
> «Сделай hardening и настрой автобэкапы»

Что будет происходить:

1. Диагностика. Агент сообщает, что нашёл, и не начинает без твоего подтверждения.
2. Разделы по порядку, с пропуском уже сделанного. После каждого — проверка результата и
   запись в паспорт сервера.
3. Перед sshd и UFW — гейт: агент проверит семь пунктов и взведёт таймер отката, а если
   что-то не выполнено, остановится и скажет, что именно.
4. Три шага требуют живого терминала, потому что у агента его нет: `ssh-keygen` с passphrase,
   первый `ssh-copy-id` с паролем хостера и sudo-пароль в безопасном режиме. Их ты делаешь в
   **отдельном окне терминала**, в любой среде: у префикса `!` в Claude Code терминала тоже
   нет, пароль через него ввести нельзя (проверено). Скилл говорит, как открыть это окно в
   Claude Desktop, VS Code, JetBrains и обычном терминале. Результат агент проверяет сам по
   ключу, а не по вставленному выводу.
5. Пароли не проходят через чат. Пароль хостера вводишь один раз в `ssh-copy-id`, новые пароли
   root и пользователя генерирует и ставит `scripts/set-passwords.sh` через `chpasswd` по
   stdin, печатая только статус. Ты сохраняешь их в менеджер паролей и удаляешь файл.
6. Для sudo агент один раз честно предложит два режима и не выберет сам:
   - **Безопасный.** Каждую sudo-команду запускаешь ты в своём терминале, пароль остаётся у
     тебя. Медленнее и больше ручной работы. Для первого раза и для сервера с данными.
   - **Быстрый.** Временный sudo без пароля на время настройки: отдельный файл, снимается
     автоматически через 4 часа и вручную в конце, диагностика и чеклист ловят забытый.
     Удобнее, но в это окно ключ SSH равен root без барьера. Для чистого сервера, когда ты рядом.

   Постоянный NOPASSWD «ради удобства» скилл запрещает в любом режиме.

**Руками.** Открой [`SKILL.md`](SKILL.md) и [`references/backups.md`](references/backups.md)
и иди по разделам. У ключевых проверок показан ожидаемый вывод, чтобы было понятно, что
«получилось» выглядит именно так.

## ⚠️ Прежде чем начать

- **Это руководство, а не автоустановщик.** Единственный скрипт здесь — диагностика, и она
  ничего не меняет. Каждый шаг делается осознанно и проверяется.
- **Консоль провайдера нужна до начала.** Гейт первым пунктом требует открыть VNC/Serial
  консоль в панели хостера. Без неё ошибка в sshd = потеря сервера.
- **Сначала потренируйся на одноразовом VPS.** Дешёвый сервер на час, пройти скилл целиком,
  сломать, пересоздать. Потом боевой.
- **Дефолты строгие намеренно.** sudo с паролем, никаких отключённых проверок «ради удобства».
  Это для прода, а не для песочницы.

## 🪶 Потребление ресурсов (для скромных VPS)

В покое обвязка почти ничего не ест и живёт на 1 ГБ RAM / 1 vCPU. Ресурсы съедает приложение,
а не настройка сервера.

| Компонент | RAM в покое | CPU в покое | Диск (пакеты) |
|-----------|-------------|-------------|---------------|
| fail2ban | ~15–30 МБ | ~0 | ~5 МБ |
| UFW | ~0 (правила в ядре) | 0 | — |
| unattended-upgrades, таймеры, cron | ~0 (по расписанию) | 0 | ~10 МБ |
| nginx (если ставишь) | ~5–10 МБ | ~0 | ~15 МБ |
| restic | 0 в покое | 0 | ~25 МБ |
| **Итого обвязка** | **~30–50 МБ** | **~0%** | **~50–150 МБ** |

Пики ночные и короткие: `apt upgrade` и restic дают всплеск на несколько минут, для этого
в инструкции есть swap. Если VPS совсем скромный: Docker самый прожорливый и опциональный
(~50–80 МБ RAM плюс образы), swap на маленьком диске делай 1 ГБ вместо 2, проверку
целостности restic можно проредить до `1/90`, fail2ban оставляй.

## 🔬 Что проверено, а что нет

- `scripts/diagnose.sh` прогнан на трёх живых серверах Ubuntu 26.04.1: два настроенных по
  своим схемам (restic + rclone + Gatus, acme.sh вместо certbot) и один чистый образ VDSina.
  Ложных вердиктов не осталось; на чистом образе пойман удалённый хостером пакет
  `unattended-upgrades` при лежащем «правильном» конфиге.
- **Уровень 1 пройден сквозняком** на чистом VDSina 26.04.1 (1 vCPU, 1 ГБ, 10 ГБ) свежей
  сессией агента вслепую по этому тексту, 28 минут вместе с ручными шагами. Все находки того
  прогона внесены: `!` без терминала, таймеры на абсолютное время, `00-hardening.conf`,
  `ssh-add`, `ufw --force`, бэкапы вне `*.d`, размер swap под диск. Уровень 2 — в процессе.
- Нашёл расхождение — открывай issue с выводом `diagnose.sh`.
