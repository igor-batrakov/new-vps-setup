# new-vps-setup

Скилл для Claude Code и совместимых агентов, который проводит через настройку Ubuntu-сервера:
от пароля хостера до сервера, который сам ставит обновления безопасности, делает бэкапы и
сообщает о проблемах в Telegram. Тот же текст читается как инструкция без агента.

Для кого: человек, который настраивает VPS впервые или получил сервер, настроенный кем-то
другим. Что нужно: сервер с Ubuntu 22.04, 24.04 или 26.04 LTS, root-пароль или ключ от
хостера, менеджер паролей и час времени на первый уровень. Локальная машина любая: Linux,
macOS или Windows.

## Чем отличается от чеклистов «что сделать после установки Ubuntu»

Обычный чеклист перечисляет команды. Здесь к ним добавлены три вещи, и каждая родилась из
реальной потери доступа или молчаливой поломки.

Перед любой правкой SSH или файрвола идёт гейт: консоль провайдера открыта и в ней выполнен
вход, вторая SSH-сессия живёт, ключ проверен, конфиги забэкаплены, таймер отката взведён.
Если новая сессия не откроется, через пять минут сервер сам вернёт прежний конфиг.

Диагностика ставит вердикт каждой проверке и печатает план в два блока: что закрыть сначала,
чтобы сервер можно было оставить включённым, и что потом, чтобы назвать его продом. Сервер,
настроенный по другой схеме, получает пометку «своя схема», а не ложное «плохо».

Правила для агента закрывают типовые провалы автоматизации: команды на сервер уходят только
скриптом из файла, результат проверяется по содержимому, а пароли и passphrase никогда не
проходят через чат. Три шага, где нужен ввод пароля, человек делает в отдельном окне
терминала, и скилл говорит, как его открыть в Claude Desktop, VS Code и обычном терминале.

## Три уровня

| Уровень | Что получается | Разделы | Время |
|---------|----------------|---------|-------|
| 1. Сервер можно оставить включённым | Вход только по ключу, root и пароль закрыты, UFW, автообновления безопасности, fail2ban | 0, 1, 2 | около часа, одна сессия |
| 2. Это прод | Бэкап с проверенным восстановлением и алертом о падении, HTTPS, алерты о диске, памяти и упавших сервисах, паспорт сервера, контрольная перезагрузка | 3–9 | полдня и неделя наблюдения за алертами |
| 3. По потребности | VPN, DOCKER-USER, смена порта SSH, апгрейд LTS, глубокий аудит, автообновление образов | отдельный скилл | [ubuntu-server-admin](https://github.com/igor-batrakov/ubuntu-server-admin) |

После первого уровня сервер защищён от взлома, но потеря диска означает потерю всего. Продом
он становится после второго. Третий уровень вынесен в другой скилл, чтобы у новичка перед
глазами было только необходимое.

## Быстрый старт: проверить существующий сервер

Три команды показывают состояние сервера и план, ничего не устанавливая и не меняя:

```bash
git clone https://github.com/igor-batrakov/new-vps-setup.git
scp new-vps-setup/scripts/diagnose.sh <user>@<server>:/tmp/
ssh -t <user>@<server> sudo bash /tmp/diagnose.sh
```

Скрипт читает `sshd -T`, UFW, sudoers, таймеры systemd, Docker, fail2ban, сертификаты через
`nginx -T`, бэкапы и алерты. Каждая проверка получает `[OK]`, `[!!]` или `[..]`, в конце
печатается список «сначала» и «потом» с номерами разделов SKILL.md, куда идти.

## Установка

```bash
# Claude Code
git clone https://github.com/igor-batrakov/new-vps-setup.git ~/.claude/skills/new-vps-setup

# Codex, Copilot CLI, Gemini CLI
git clone https://github.com/igor-batrakov/new-vps-setup.git ~/.agents/skills/new-vps-setup
```

После перезапуска сессии скилл включается сам по смыслу запроса.

## Как проходит настройка с агентом

Запрос вроде «помоги настроить новый Ubuntu VPS под продакшн» или «проверь мой сервер и
скажи, что не так» запускает такой порядок.

1. Диагностика. Агент рассказывает, что нашёл, и ждёт подтверждения, прежде чем что-то менять.
2. Разделы по порядку с пропуском уже сделанного: у каждого есть проверка «уже сделано,
   если». После раздела агент проверяет результат и записывает его в паспорт сервера.
3. Перед правкой sshd и включением UFW агент проходит гейт из семи пунктов и взводит таймер
   отката. Если пункт не выполнен, он останавливается и называет, какой.
4. Три шага требуют ввода пароля, поэтому их выполняет человек в отдельном окне терминала:
   `ssh-keygen` с passphrase, первый `ssh-copy-id` с паролем хостера и sudo-пароль в
   безопасном режиме. У агента терминала нет, у префикса `!` в Claude Code тоже. Результат
   агент проверяет сам по ключу.
5. Пароли не проходят через чат. Пароль хостера вводится один раз и сразу заменяется. Новые
   пароли root и пользователя генерирует `scripts/set-passwords.sh` и ставит через `chpasswd`
   по stdin, печатая только статус. Пароль репозитория restic и токен Telegram-бота вводятся
   скрытым вводом в терминале и живут только в файлах с правами 600 на сервере.
6. Для sudo агент один раз предлагает два режима и не выбирает сам. Безопасный: каждую
   sudo-команду запускает человек и вводит пароль. Быстрый: временный sudo без пароля на время
   настройки, отдельным файлом, снимается автоматически через четыре часа и вручную в конце.
   В быстром режиме ключ SSH на это время равен root без барьера, скилл говорит об этом прямо.
   Постоянный NOPASSWD запрещён в любом режиме.
7. Бэкап и Telegram-алерты агент предлагает, а решает человек. Для бэкапа три варианта:
   снапшоты хостера, restic в стороннее хранилище, отказ с записью в паспорт. Пропуск алертов
   тоже записывается в паспорт вместе с последствием: о падении бэкапа никто не сообщит.

Без агента порядок тот же: SKILL.md и [references/backups.md](references/backups.md) читаются
как инструкция, у ключевых проверок показан ожидаемый вывод.

## Что внутри

| Часть | Содержание |
|-------|------------|
| Правила для агента | Команды только из файла, конфиги через `scp` и `install`, проверка по содержимому, ручные шаги по таблице сред, два режима sudo, пароли мимо чата |
| Гейт от «я заперся» | Семь проверок перед правкой sshd и UFW, таймер отката на абсолютном времени, объективная проверка консоли и второй сессии через `loginctl` |
| 0. Диагностика | `scripts/diagnose.sh`, карта «нашёл → раздел», проверки «уже сделано, если» |
| 1. Hardening | Ключ ed25519 и `ssh-add`, sudo-пользователь с паролем, дефолтный пользователь хостера заперт, `00-hardening.conf` поверх cloud-init, `unattended-upgrades` с проверкой пакета и таймеров, fail2ban с `backend = systemd`, лимит журнала, swap под размер диска |
| 2. Файрвол | UFW: закрыто всё, открыто нужное, админки только доверенным IP |
| 3. Docker | Лог-ротация, `restart: unless-stopped`, порты на `127.0.0.1`, потому что Docker обходит UFW |
| 4. nginx и HTTPS | Reverse proxy, Let's Encrypt с автопродлением |
| 5. Алерты | Telegram: диск, память, «нужна перезагрузка», упавшие сервисы, бэкап. Сообщения с эмодзи, что случилось и что делать |
| 6. Бэкапы | Выбор способа; для restic: ротация, восстановление с побайтной сверкой, сквозной тест алерта, dead-man's switch по желанию |
| 7. Регламент | Что делает автоматика, что человек раз в неделю, месяц и полгода |
| 8. Pitfalls | Шестнадцать вещей, которые нельзя делать |
| 9. Финал | `ssh-audit` и `lynis`, контрольная перезагрузка, паспорт сервера, уборка, чеклист |
| 10. Runbook «Я заперся» | В `references/lockout.md`: симптом, причина, что делать через консоль провайдера |
| Runbook «Сервер умер» | В `references/backups.md`: новый VPS, restic, данные и БД из дампа, `/etc` выборочно |

Разделы 3 и 4 нужны только серверам с контейнерами и сайтом. Остальные проходятся всегда.

## Перед началом

Это руководство, а не автоустановщик: единственный скрипт, который запускается на сервере
без вопросов, читает и ничего не меняет. Каждый шаг делается отдельно и проверяется.

Консоль провайдера нужна до первого опасного шага. Гейт требует открыть VNC или Serial в
панели хостера и войти там, потому что ошибка в sshd без консоли означает потерю сервера.

Первый раз лучше пройти на одноразовом VPS: почасовой сервер стоит копейки, а сломать и
пересоздать его безопасно. Дефолты скилла строгие: sudo с паролем, никаких отключённых
проверок ради удобства.

## Потребление ресурсов

В покое обвязка занимает 30–50 МБ памяти и почти не тратит процессор, поэтому живёт на
1 ГБ RAM и одном vCPU.

| Компонент | RAM в покое | CPU в покое | Диск |
|-----------|-------------|-------------|------|
| fail2ban | 15–30 МБ | около нуля | 5 МБ |
| UFW | около нуля, правила в ядре | 0 | — |
| unattended-upgrades, таймеры, cron | около нуля | 0 | 10 МБ |
| nginx, если ставится | 5–10 МБ | около нуля | 15 МБ |
| restic | 0 в покое | 0 | 25 МБ |

Пики короткие и ночные: `apt upgrade` и restic нагружают сервер на несколько минут, для этого
в инструкции есть swap. На 10-гигабайтном диске swap делается размером 1 ГБ, а после
обновлений выполняется `apt-get clean`: кэш пакетов после первого апгрейда занимает до
гигабайта. Docker прожорливее всего остального вместе и остаётся опциональным.

## Что проверено

- `scripts/diagnose.sh` прогнан на трёх серверах Ubuntu 26.04.1: два с собственными схемами
  бэкапов и алертов (restic, rclone, Gatus, acme.sh) и один чистый образ VDSina. На чистом
  образе диагностика поймала удалённый хостером пакет `unattended-upgrades` при лежащем
  «правильном» конфиге.
- Уровни 1 и 2 пройдены с нуля на чистом VDSina 26.04.1 (1 vCPU, 1 ГБ RAM, 10 ГБ диска)
  свежей сессией агента, которая шла только по этому тексту: 54 минуты вместе с ручными
  шагами, без Docker и nginx, restic в локальный учебный репозиторий. Двадцать шесть
  находок того прогона внесены в текст.
- Повторный прогон hardening, алертов, бэкапов и уборки по обновлённому тексту занял 12 минут и
  подтвердил три скрипта, таймеры на абсолютном времени, `00-hardening.conf`, сквозной тест
  `OnFailure` и восстановление с побайтной сверкой.

Не проверялось: смена порта SSH под `ssh.socket` на живом сервере и путь с Docker и nginx.
Расхождение с реальностью лучше всего присылать issue с выводом `diagnose.sh`.

## Структура репозитория

```
new-vps-setup/
├── SKILL.md              # правила для агента, гейт, разделы 0–10
├── references/
│   ├── backups.md        # restic: скрипт, таймер, алерты, восстановление, runbook «сервер умер»
│   ├── lockout.md        # runbook «я заперся»: симптомы и команды для консоли провайдера
│   └── passport.md       # шаблон паспорта сервера /root/server-notes.md
├── scripts/
│   ├── diagnose.sh       # read-only диагностика с вердиктами и планом по уровням
│   ├── set-passwords.sh  # локально: пароли root и sudo через chpasswd, ничего не печатает
│   ├── tg-setup.sh       # на сервере: токен бота скрытым вводом, chat_id определяется сам
│   └── restic-env.sh     # на сервере: пароль репозитория показывается один раз
└── assets/
    ├── demo.gif          # схема для этого README
    └── make_demo.py      # генератор схемы: python3 assets/make_demo.py assets/demo.gif
```

или pull request.
